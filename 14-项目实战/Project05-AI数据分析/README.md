# Project05 - AI 数据分析（可直接运行的真实统计 Demo）

> 一个**真正会算**的数据分析系统：粘贴 / 上传 CSV，它会用本地统计引擎**真实计算**数据摘要、趋势（线性回归）、异常（Z-score）与相关性（Pearson），并用零依赖图表展示结果。
> 技术栈 `React + TypeScript + Vite + Express`。**不配置任何 API Key 也能完整使用**（本地引擎真实计算）；配置 `OPENAI_API_KEY` 后，大模型会**基于真实统计数字**撰写专业叙述与建议——而不是编造指标。

## 一、这个项目和「假分析 Demo」的区别

很多数据分析 Demo 的洞察是**写死的**：无论你输入什么数据，它都回「月均增长 8.5%」「r=0.92」。本项目刻意把这层补成真的：

- ✅ **数字是算出来的**：均值、中位数、标准差、回归斜率、R²、Pearson r、Z-score 全部由 `server/services/stats.ts` 真实计算，换数据就换结果。
- ✅ **图表是真实派生的**：直方图按真实分箱、趋势折线是真实序列、异常柱状图会把真正越界的点标红。
- ✅ **离线可用**：无需 API Key、无需任何第三方库（连图表库都没用），纯本地即可演示。
- ✅ **API 模式不编造**：大模型只拿到「已经算好的真实统计」去做叙述，提示词明确「严禁编造未给出的数字」——这正是用 LLM 做数据解读的正确姿势。
- ✅ **优雅降级**：配了 Key 但模型调用失败时，自动回退到本地真实计算结果。

## 二、四种分析分别真实计算了什么

| 分析类型 | 真实计算内容 | 典型用途 |
| --- | --- | --- |
| **数据摘要** summary | 每列类型识别、计数/缺失、数值列的 min/max/mean/median/std、类别列的去重数与 Top 值、首数值列直方图 | 快速体检一份数据 |
| **趋势分析** trend | 对每个数值列按行序做一元线性回归：斜率、R²、首末变化率、方向（升/降/平） | 看增长/下滑 |
| **异常检测** anomaly | 每个数值列的 Z-score，标出 \|Z\| ≥ 2 的异常点（行号、数值、偏离标准差数） | 找脏数据/突刺 |
| **相关性** correlation | 所有数值列两两的 Pearson 相关系数，按 \|r\| 排序并给强度描述 | 找指标间关系 |

内置 3 份示例数据（点按钮一键填充）：**月度销售**（趋势/相关性）、**服务器监控**（含异常突刺）、**学习时长与成绩**（强相关）。

## 四、运行方式

```bash
# 1. 安装依赖（根目录 + server）
pnpm install
cd server && pnpm install && cd ..

# 2.（可选）配置环境变量
cd server && cp .env.example .env && cd ..
#   留空 OPENAI_API_KEY = 本地真实统计；填写后 = 模型基于真实统计做叙述

# 3. 启动（两个终端）
cd server && pnpm dev      # 后端，默认 http://localhost:3000
pnpm dev                   # 前端，默认 http://localhost:5173
```

- 前端页面：`http://localhost:5173`
- 健康检查：`http://localhost:3000/health`（返回当前 `mock` / `api` 模式）

> 环境变量：`OPENAI_API_KEY`、`OPENAI_MODEL`（默认 `gpt-4o-mini`）、`OPENAI_BASE_URL`（可接 DeepSeek 等兼容服务）、`PORT`。

## 五、API 接口

| 方法 | 路径 | 说明 |
| --- | --- | --- |
| `POST` | `/api/analyze` | 解析数据并执行真实统计分析，返回结论/洞察/图表/列统计 |
| `GET` | `/api/samples` | 列出内置示例数据集与当前模式 |
| `GET` | `/api/samples/:key` | 取单个示例 |
| `GET` | `/health` | 健康检查 |

`POST /analyze` 请求体：`{ "data": "<CSV 文本>", "type": "summary|trend|anomaly|correlation" }`。

`curl` 快速验证（启动后端后）：

```bash
curl -X POST http://localhost:3000/api/analyze \
  -H 'Content-Type: application/json' \
  -d '{"data":"x,y\n1,2\n2,4\n3,6\n4,8","type":"correlation"}'
# 返回 x~y 的 r=1（完全正相关）——真实计算
```

## 六、两种模式的工作原理

```
CSV 文本 ──► parser.ts 解析+列类型推断 ──► stats.ts 真实统计计算
                                              │
                  ┌───────────────────────────┴───────────────────────────┐
              mock 模式                                                 api 模式
        直接返回真实计算结果                          把真实统计(JSON)喂给大模型，
        （数字+图表+洞察）                            让它基于真实数字撰写专业叙述
                                                      （严禁编造，失败则降级为本地结果）
```

关键点：**统计永远是本地真实算的**，API Key 只决定「结论文字」是模板合成还是模型润色。这样既保证数字可信，又能在有 Key 时获得更自然的业务解读。

## 七、动手练习

1. **改阈值看异常**：把 `stats.ts` 里异常检测的 `Z_THRESHOLD = 2` 改成 1.5，观察异常点变多。
2. **换检测方法**：把 Z-score 换成 IQR（四分位距）法，对比两种异常判定的差异。
3. **加一种分析**：新增「分组聚合」——按某类别列分组，对数值列求和/均值（类似 SQL 的 GROUP BY）。
4. **接真实可视化**：把 `SimpleChart` 换成 ECharts / Recharts，支持散点图看相关性。
5. **大文件流式解析**：当前一次性读入，试着改成按行流式解析以支持大 CSV。

## 八、如果你是产品经理，重点观察什么

1. **「会展示」与「算得对」是两件事**：本项目让你看清，一个数据产品的可信度下限取决于计算层，而不是 UI。
2. **LLM 在数据分析里的正确位置**：不是让它「猜数字」，而是让它「解读已经算好的真实数字」——这与 RAG「先检索再生成」是同一种思路（用事实约束模型）。
3. **可解释性**：每个结论都能追溯到具体的统计量（r、Z、R²），这是数据产品进入业务决策的前提。
4. **能力边界**：当前是单文件、内存计算的分析工具，不是接入数仓、含权限与调度的 BI 平台——但它把「分析内核」这层做实了。

> 我做了一个可直接运行的 AI 数据分析工具：自研了零依赖的 CSV 解析与统计引擎，**真实计算**数据摘要、线性回归趋势、Z-score 异常检测与 Pearson 相关性，并用纯 DOM/SVG 渲染图表。它有两种模式——本地真实统计（离线可用）与「大模型基于真实统计做叙述」（严禁编造、可优雅降级）。这个项目让我清楚区分了数据产品的计算层、解读层与展示层，也让我理解了用 LLM 做数据解读时如何用真实事实约束模型、避免幻觉。

## 十一、最小复盘模板

1. 为什么把「计算」和「叙述」分成两层？各自由谁负责？
2. mock 模式输出的数字和 API 模式输出的数字，会不一样吗？为什么？
3. Z-score 异常检测在什么数据分布下会失效？还能用什么方法替代？
4. 让 LLM「解读真实统计」与让它「直接分析原始数据」，可信度差别在哪？
5. 要把这个工具推向企业 BI，第一个要补的能力是什么，为什么？
