## 四、数据使用评审

- 数据来自哪里，谁是 Data Owner，采集和使用依据是什么？
- 是否包含个人、敏感、机密、受版权保护或受合同限制的数据？
- 数据是否会离开既定区域，是否进入第三方或其子处理方？
- Provider 是否可将输入、输出或反馈用于训练？默认应明确禁止或获得授权。
- 检索和工具调用是否继承源系统权限，缓存是否可能绕过权限？
- 日志、评测集、人工审核平台会复制哪些数据，保留多久？
- 用户如何访问、更正、删除或提出异议？退役时如何删除和证明？

## 六、AI 事件分级与响应

| 级别 | 示例 | 首要动作 | 通知 |
| --- | --- | --- | --- |
| P0 | 大规模敏感数据泄漏、不可逆高影响误操作 | 立即熔断、保全证据、启动危机机制 | 高管、安全、法务/隐私、业务 |
| P1 | 关键业务大面积错误、权限控制失效 | 降级/回滚、限制范围、人工接管 | 服务 Owner、产品、风险团队 |
| P2 | 局部质量退化、成本或延迟异常 | 暂停扩量、定位切片、排期修复 | 产品、研发、运营 |
| P3 | 单个低风险 Bad Case | 进入样本库和常规迭代 | 产品 Owner |

事件记录必须包含：发现渠道、时间线、受影响范围、模型/Prompt/策略/数据版本、即时控制、根因、通知、恢复、永久修复和新增回归用例。

## 七、季度复核单

- [ ] 用途、用户和自动化程度是否发生变化？
- [ ] 数据源、权限、区域、供应商或子处理方是否变化？
- [ ] 黄金集是否覆盖最新流量和事件，领域专家是否重新校准？
- [ ] 关键切片质量、SLO、成本和风险是否仍在阈值内？
- [ ] 用户是否过度依赖，人工监督是否真实有效？
- [ ] 合同、法规、内部政策或协议规范是否变化？
- [ ] 是否仍值得继续，还是应缩减、替换或退役？

## 八、退役清单

- [ ] 通知用户、业务 Owner、运维、数据与风险团队。
- [ ] 停止入口、计划任务、Agent 委派、MCP 工具和外部集成。
- [ ] 撤销服务账号、API Key、OAuth Grant、证书和网络权限。
- [ ] 按政策导出/归档必要记录，删除输入、缓存、索引、记忆和临时数据。
- [ ] 要求供应商完成删除并提供证明。
- [ ] 迁移未完成任务和用户流程，保留必要人工通道。
- [ ] 更新资产清单、架构图、CMDB、风险登记册和成本中心。
- [ ] 复盘业务结果、风险事件、技术债和可复用资产。

## 九、治理效果指标

| 目标 | 指标 |
| --- | --- |
| 覆盖 | 已登记 AI 用例比例、按期复核率、模型/系统卡覆盖率 |
| 质量 | 回归门禁拦截率、生产逃逸缺陷、风险切片通过率 |
| 响应 | 事件发现时间、熔断时间、恢复时间、整改关闭周期 |
| 权限 | 高风险动作审批覆盖率、凭证轮换率、越权事件 |
| 价值 | 用例 ROI 达标率、停止低价值用例数量、平台复用率 |

治理团队不能只追求“审批数量”，还应减少重复控制、缩短低风险用例交付时间，并提高高风险问题的发现和响应能力。
