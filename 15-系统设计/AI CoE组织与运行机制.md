# AI CoE 组织与运行机制

> AI CoE（Center of Excellence）不是单独的“创新部门”，而是连接战略、平台、业务域、风险和交付团队的运行机制。目标是让企业安全地扩大有效用例，同时能停止低价值项目。

## 一、推荐组织模型

```text
AI Steering Committee（战略、预算、风险接受）
          │
AI CoE（标准、平台、评测、赋能、组合经营）
   ┌──────┼────────┬────────┐
业务域 Owner  平台/架构  数据/安全/法务  运营/FinOps
```

## 二、职责分工

| 角色 | 负责 | 不负责 |
| --- | --- | --- |
| Steering Committee | 战略、预算、高风险接受、停止重大项目 | 日常 Prompt 调参 |
| AI CoE 产品 | 能力地图、标准、平台路线、用例组合 | 替代业务 Owner 定义问题 |
| 业务域 AI Owner | 业务基线、流程、样本、采用和结果 | 单独决定安全/法务例外 |
| 平台/架构 | 模型网关、RAG/Agent、身份、观测、可靠性 | 单独承诺业务 ROI |
| 数据/安全/法务 | 数据用途、控制、红队、合规和事件 | 替业务决定优先级 |
| FinOps/运营 | 成本、配额、SLO、反馈和服务运营 | 用成本指标替代业务价值 |

## 三、用例准入分层

| 类别 | 特征 | 流程 |
| --- | --- | --- |
| A 低风险 | 只读、内部、可逆、无敏感数据 | 模板自助 + 自动门禁 |
| B 中风险 | 机密数据、跨系统、建议影响业务 | CoE 评审 + 灰度 + 业务签字 |
| C 高风险 | 高敏数据、高影响决策、不可逆写入 | 安全/法务/高管会签 + 人工监督 |
| D 禁止自治 | 法律最终决定、重大人事/信用/医疗决定等 | 仅允许辅助，不得自动决策 |

## 四、标准服务目录

- 模型与供应商路由、凭证、配额和弃用管理。
- Prompt/策略/工具版本与发布回滚。
- 黄金数据集、评测、红队、Bad Case 和回归门禁。
- RAG 数据接入、权限过滤、索引与新鲜度。
- Agent 运行、工具注册、审批、审计、终止和补偿。
- Trace、质量、SLO、成本、风险和业务结果看板。
- 项目模板、架构评审、培训、Office Hours 和案例资产库。

## 五、季度组合经营

每季度对所有用例打分：

```text
组合得分 = 业务价值 × 采用证据 × 可复用性
          - 运行成本 - 风险暴露 - 供应商锁定 - 变更复杂度
```

评审输出：扩量、保持、重构、迁移、暂停或退役。停止项目是 CoE 的正常职责，不应只用“上线数量”评价团队。

## 六、CoE 运行指标

| 目标 | 指标 |
| --- | --- |
| 价值 | 达到 ROI 目标的用例比例、采用率、任务成功率、业务节省/收入 |
| 复用 | 平台能力复用率、重复集成减少量、从立项到灰度时间 |
| 质量 | 回归门禁拦截率、生产逃逸缺陷、Bad Case 关闭周期 |
| 风险 | 高风险审批覆盖率、越权事件、事件响应时间、按期复核率 |
| 经济性 | 单成功任务成本、毛利、预算偏差、供应商集中度 |
| 组织 | 完成认证人数、业务域自主交付数、标准采用率 |

## 七、90 天落地节奏

| 时间 | 动作 | 交付物 |
| --- | --- | --- |
| 0–30 天 | 盘点用例、数据、供应商、风险和成本 | AI 资产清单、分层规则、三项试点 |
| 31–60 天 | 建立最小平台和门禁 | 评测集、模型网关、权限/审计、发布模板 |
| 61–90 天 | 用三个业务域验证复用和治理 | 组合看板、复盘、扩量/停止决策 |

## 八、成熟度验收

- [ ] 有 Steering Committee、CoE、业务 Owner 和风险 Owner。
- [ ] 所有 AI 用例已登记、分级并有复核日期。
- [ ] 低风险可自助，高风险有会签，禁止自治有明确边界。
- [ ] 平台复用、业务结果、质量、风险和成本同时度量。
- [ ] CoE 能够推动扩量，也能够有证据地停止项目。
