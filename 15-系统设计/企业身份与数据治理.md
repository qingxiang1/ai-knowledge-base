# 企业身份与数据治理

> 企业 AI 项目最常见的上线阻塞，不是模型能力，而是“谁能访问什么、数据能否用于什么、Agent 能代表谁行动”。本章把这些问题转成产品和架构可共同评审的设计。

## 一、四种身份必须分开

| 身份 | 代表谁 | 典型凭证 | 产品必须控制 |
| --- | --- | --- | --- |
| 人类用户 | 发起任务的人 | SSO/OIDC 会话、设备信任 | 用户可访问范围、同意和申诉 |
| 工作负载 | 应用/Agent 服务 | 短期服务 Token、mTLS、Workload Identity | 服务能调用的系统和工具 |
| 租户/组织 | 数据与计费边界 | tenant_id、部门/地域声明 | 数据隔离、配额、成本分摊 |
| 审批人 | 对高风险结果负责的人 | 强认证、审批记录 | 谁确认、确认了什么、何时过期 |

禁止让 Agent 直接复用用户长期 Token，也不能把“用户拥有权限”自动等同于“Agent 可以无条件执行”。

## 二、RBAC 与 ABAC

### RBAC 适合

- 角色稳定、组织层级清晰的功能访问。
- 例如客服、主管、知识库管理员、审计员。

### ABAC/策略引擎适合

- 访问结果取决于用户、租户、资源分类、地域、时间、用途和风险。
- 例如：客服可以查看本租户订单，但不能查看其他租户；Agent 可读订单，但只能创建草稿，不能直接退款。

策略应以“主体 + 动作 + 资源 + 条件 + 目的”表达，并在服务端重新判断：

```text
allow(user, action, resource, context)
where user.tenant == resource.tenant
  and user.role includes required_role
  and context.purpose == approved_purpose
  and risk_policy(action) <= granted_level
```

## 三、数据分类与最小使用

| 等级 | 示例 | 默认 AI 策略 |
| --- | --- | --- |
| L0 公开 | 官网、公开政策 | 可用于普通模型，仍需防 Prompt Injection |
| L1 内部 | 流程、非敏感运营文档 | 需组织权限和审计，禁止公开分享 |
| L2 机密 | 客户、财务、代码、合同 | 权限检索、脱敏、区域/供应商审查 |
| L3 高敏 | 身份、健康、薪酬、未公开交易 | 默认禁止外发；专用环境、强审批、最小日志 |

分类必须贯穿：原始数据、解析文本、Chunk、Embedding、缓存、Prompt、模型输入输出、Trace、评测集和备份。Embedding 也可能泄露语义，不应被视为“非敏感副本”。

## 四、数据用途契约

每个数据源接入前记录：

- Owner、来源系统、分类、地域和授权依据。
- 允许用途、禁止用途、是否允许供应商处理/训练。
- 可访问角色、字段范围、检索过滤和导出限制。
- 留存期限、删除 SLA、缓存/索引/Embedding 清理方式。
- 质量、新鲜度、版本、血缘和回滚方式。
- 跨租户、跨区域、跨境和第三方子处理方路径。

## 五、Agent 与工具授权

工具至少分为只读、可逆写入、高风险写入和禁止自治四级。对写操作：

1. 服务端校验用户授权与 Agent 任务授权。
2. 重新校验模型传入的参数、租户、金额、对象和幂等键。
3. 高风险动作展示影响范围、目标对象和撤销方式。
4. 审批记录绑定任务、版本、输入摘要和最终执行结果。
5. 超时、取消、重试和下游重复调用不会扩大权限或重复产生副作用。

## 六、日志与隐私

- 默认记录决策所需元数据，不默认保存完整敏感 Prompt/上下文。
- 对用户、客户、合同、代码和凭证做字段级脱敏或令牌化。
- 调试采样需有授权、采样率、访问审批和到期时间。
- 审计日志不可被业务管理员静默修改，且与业务日志分权。
- 用户可以知道数据如何用于 AI，并按政策访问、更正或删除。

## 七、企业评审问题

- 这项 AI 能代表谁？它的权限边界如何验证？
- 用户权限变更后，缓存、Embedding、长期记忆多久失效？
- 数据删除如何影响索引、评测集、日志和模型微调数据？
- 同一工具被不同租户调用时，如何防止参数和结果串租户？
- 供应商或区域切换时，数据如何迁移或删除？
- 谁能查看 Trace，谁能批准高风险动作，谁能接受剩余风险？

## 八、验收清单

- [ ] 人类、工作负载、租户和审批人身份已分离。
- [ ] 访问策略覆盖用户、资源、动作、条件和用途。
- [ ] 数据分类贯穿原始数据到 Embedding、缓存、日志和备份。
- [ ] 高敏数据无未经批准的第三方传输或训练用途。
- [ ] Agent 工具调用有最小权限、服务端校验、审批和审计。
- [ ] 数据删除、权限撤回、迁移和供应商退出可演练。
